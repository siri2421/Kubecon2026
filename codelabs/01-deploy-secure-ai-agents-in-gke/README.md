# Codelab 1: Deploy Secure AI Agents on GKE
### *Isolating Untrusted Agent Execution with gVisor, Workload Identity & Egress Governance*

**Duration:** ~25 minutes  
**Level:** Intermediate / Advanced  
**Focus:** GKE Platform Engineering, Zero-Trust Agent Sandboxing, IAM Federation

---

## 🎯 What You Will Build

In this codelab, you will implement the **Platform Boundaries** shown in the KubeCon talk for running untrusted autonomous agents safely on Google Kubernetes Engine:

1. **Runtime Isolation:** Configure **gVisor (`runsc`)** sandbox execution for agent code interpreters to prevent host kernel exploits.
2. **Warm Pools:** Deploy a `SandboxWarmPool` to eliminate cold-start container latency for dynamic Python/Bash execution.
3. **Keyless Identity:** Bind a Kubernetes Service Account (KSA) to Google Cloud IAM using **Workload Identity Federation** (zero static keys).
4. **Egress Lockdown:** Apply a Kubernetes `NetworkPolicy` restricting outbound egress exclusively to the Agent Gateway and blocking the GCP Metadata Server (`169.254.169.254`).
5. **Admission Defense:** Enforce a `ValidatingAdmissionPolicy` that rejects any agent-runner pod not specifying `runtimeClassName: gvisor`.

---

## 🛠️ Step 1: Create Namespace & Workload Identity

Create the workload namespace and bind the agent's Kubernetes Service Account directly to Google Cloud IAM:

```bash
kubectl create namespace finance-workloads

# Create Google Cloud IAM Service Account
gcloud iam service-accounts create invoice-agent-runner \
    --description="IAM Service Account for Invoice Agent on GKE" \
    --display-name="invoice-agent-runner"

# Grant least-privilege read access (e.g. BigQuery data viewer)
gcloud projects add-iam-policy-binding $PROJECT_ID \
    --member="serviceAccount:invoice-agent-runner@${PROJECT_ID}.iam.gserviceaccount.com" \
    --role="roles/bigquery.dataViewer"

# Allow Kubernetes Service Account to impersonate the IAM Service Account via SPIFFE
gcloud iam service-accounts add-iam-policy-binding \
    invoice-agent-runner@${PROJECT_ID}.iam.gserviceaccount.com \
    --role="roles/iam.workloadIdentityUser" \
    --member="serviceAccount:${PROJECT_ID}.svc.id.goog[finance-workloads/invoice-agent-sa]"
```

Now apply [`01-workload-identity.yaml`](./01-workload-identity.yaml):

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: invoice-agent-sa
  namespace: finance-workloads
  annotations:
    iam.gke.io/gcp-service-account: invoice-agent-runner@${PROJECT_ID}.iam.gserviceaccount.com
```

```bash
kubectl apply -f 01-workload-identity.yaml
```

## 🛡️ Step 2: Deploy gVisor Sandbox Template & Warm Pool

When an agent needs to execute untrusted user-provided Python scripts or dynamic data transformations, it must run inside a gVisor user-space kernel sandbox.

Apply [`02-agent-sandbox-template.yaml`](./02-agent-sandbox-template.yaml):

```yaml
apiVersion: extensions.agents.x-k8s.io/v1alpha1
kind: SandboxTemplate
metadata:
  name: python-runtime
  namespace: finance-workloads
spec:
  podTemplate:
    spec:
      runtimeClassName: gvisor
      automountServiceAccountToken: false
      containers:
      - name: runner
        image: python:3.12-slim
        resources:
          limits:
            cpu: "2"
            memory: "4Gi"
          requests:
            cpu: "500m"
            memory: "1Gi"
        securityContext:
          allowPrivilegeEscalation: false
          readOnlyRootFilesystem: true
          capabilities:
            drop: ["ALL"]
---
apiVersion: extensions.agents.x-k8s.io/v1alpha1
kind: SandboxWarmPool
metadata:
  name: python-warm-pool
  namespace: finance-workloads
spec:
  replicas: 2
  sandboxTemplateRef:
    name: python-runtime
```

```bash
kubectl apply -f 02-agent-sandbox-template.yaml
```

> **Why `automountServiceAccountToken: false`?**  
> Ephemeral code runner pods execute arbitrary code generated by LLMs. Under CIS Benchmark 5.1.5, code interpreter pods should never mount the Kubernetes API credential token.

## 🌐 Step 3: Enforce Default-Deny & Gateway Egress NetworkPolicy

Untrusted agents must never connect directly to third-party endpoints or scrape the cloud metadata server. All egress must traverse the **Agent Gateway**.

Apply [`03-network-policy.yaml`](./03-network-policy.yaml):

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: agent-egress-gateway-only
  namespace: finance-workloads
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/part-of: agent-workload
  policyTypes:
  - Egress
  egress:
  # 1. Allow DNS resolution inside cluster
  - to:
    - namespaceSelector: {}
      podSelector:
        matchLabels:
          k8s-app: kube-dns
    ports:
    - protocol: UDP
      port: 53
  # 2. Allow egress ONLY to Agent Gateway namespace
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: platform-gateway
      podSelector:
        matchLabels:
          role: agent-gateway
    ports:
    - protocol: TCP
      port: 8080
```

```bash
kubectl apply -f 03-network-policy.yaml
```

## 🔒 Step 4: Admission Governance (Reject Non-gVisor Pods)

Platform teams must ensure developers cannot bypass sandboxing by omitting `runtimeClassName: gvisor`.

Apply [`04-validating-admission-policy.yaml`](./04-validating-admission-policy.yaml):

```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicy
metadata:
  name: enforce-agent-sandbox
spec:
  failurePolicy: Fail
  matchConstraints:
    resourceRules:
    - apiGroups: [""]
      apiVersions: ["v1"]
      operations: ["CREATE", "UPDATE"]
      resources: ["pods"]
  matchConditions:
  - name: is-agent-runner
    expression: >-
      has(object.metadata.labels) && 
      'app.kubernetes.io/component' in object.metadata.labels &&
      object.metadata.labels['app.kubernetes.io/component'] == 'code-runner'
  validations:
  - expression: "has(object.spec.runtimeClassName) && object.spec.runtimeClassName == 'gvisor'"
    message: "Security Policy Violation: Agent code runner pods MUST run with runtimeClassName: gvisor."
---
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicyBinding
metadata:
  name: enforce-agent-sandbox-binding
spec:
  policyName: enforce-agent-sandbox
  validationActions: [Deny]
  matchResources:
    namespaceSelector:
      matchLabels:
        environment: production
```

```bash
kubectl apply -f 04-validating-admission-policy.yaml
```

## ✅ Step 5: Verification & Testing

### 1. Test Admission Policy Rejection:
Attempt to spin up an unsafe code-runner container without gVisor:

```bash
kubectl run unsafe-test --image=python:3.12-slim -n finance-workloads \
  --labels="app.kubernetes.io/component=code-runner"
```
**Expected Output:**  
`Error from server (Forbidden): admission webhook denied the request: Security Policy Violation: Agent code runner pods MUST run with runtimeClassName: gvisor.`

### 2. Verify Workload Identity Token:
Deploy a sandboxed runner with the service account and check its identity token:

```bash
kubectl exec -it deployment/invoice-agent-orchestrator -n finance-workloads -- \
  gcloud auth list
```
**Expected Output:**  
`Active Account: invoice-agent-runner@<PROJECT_ID>.iam.gserviceaccount.com`
