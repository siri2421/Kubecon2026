From SDLC to the Agentic Lifecycle 0:55–1:45

Architecture Dimension Traditional Microservices Autonomous AI Agents
Execution Flow Deterministic, single-pass code Non-deterministic reasoning loops
Compute Profile Steady CPU/Memory node pools Bursty compute + 90% waiting on I/O
Identity Model Single service-to-service IAM Delegated user identity + Agent-to-Agent (A2A)
Health Signals 200 OK = Service healthy 200 OK tells you nothing about accuracy
"Put agents on a platform built for microservices, and failure modes appear immediately."

The 4 Agent Failure Modes on Kubernetes 1:45–2:40

Failure 1

Silent Loops

Nothing crashes. Pods return 200 OK while infinite agent loops burn LLM tokens all night long.

Failure 2

Tool Sprawl

Every team wires their agent directly to unvetted MCP servers and ad-hoc third-party APIs.

Failure 3

Idle Resources

Agents hold expensive CPU, memory, and accelerator reservations while sitting idle waiting on network I/O.

Failure 4

Data Leaks

Sensitive internal data and PII leak into uninspected prompts, debug logs, or unauthorized model calls.

Don't Shift-Left: "Shift-Down" 2:40–3:25

Shift-left asked developers to become GPU schedulers and security analysts. Shift-down moves that complexity into GKE.

Layer 1: Developer Responsibility (Only what is unique)

System Prompts · Reasoning Graph (LangGraph / ADK) · Business Tool Logic

Layer 2: GKE Platform Runtime (Isolation & Scheduling)

Agent Sandbox (gVisor) · Kueue & DWS Just-in-Time Compute · Agent Substrate Snapshot/Resume

Layer 3: Enterprise Platform Services (Governance & Telemetry)

Agent Gateway (MCP Reverse Proxy) · Model Armor · Admission Policies · OpenTelemetry Tracing

1. Isolate: Agent Sandbox & Substrate 3:25–4:50

apiVersion: v1
kind: Pod
metadata:
  name: agent-code-interpreter
spec:
  # 🟨 Intercepts syscalls in user space:
  runtimeClassName: gvisor

  # Zero Kubernetes cluster credentials:
  automountServiceAccountToken: false

  containers:
  - name: python-sandbox
    image: python:3.11-slim
Default-deny NetworkPolicy keeps the pod away from cluster metadata.

Zero-Trust Execution

  • Agent Sandbox (gVisor): Safe execution of LLM-generated Python/Bash code without host kernel exposure.
  • Kueue & DWS: JIT GPU acquisition when batch jobs run, releasing silicon immediately when finished.
⚡ Agent Substrate 1.0 (GA / CNCF Sandbox)

Snapshots idle agents waiting on models or humans. Frees the pod. Resumes on any warm worker in < 0.5 seconds!

2. Identify + Guard 4:50–5:55

3 Distinct Identities

  • The User: Authenticated session token propagated with every tool action.
  • The Agent: Dedicated Kubernetes SA mapped via Workload Identity Federation (e.g. read BigQuery only, zero static keys).
  • Access: Short-lived tokens issued per call.

Audit log: "invoice-agent, acting for Alice, read table X."

2 Enforcement Guardrails

  • Model Armor: Filters prompts & responses for injection, jailbreaks, and PII.
  • Admission Policy: Rejects untrusted agent pods before they schedule!
# ValidatingAdmissionPolicy:
spec:
  validations:
  - expression: "object.spec.runtimeClassName == 'gvisor'"
    message: "Agent code pods MUST specify gVisor!"

3. Govern Tools: The Agent Gateway 5:55–6:55

Agents never call tools directly. All MCP servers, APIs, and A2A calls pass through the Gateway.

1. Approved Catalog

Agent Registry acts as enterprise source of truth.

2. RBAC Permissions

Strict per-agent tool allowlists.

3. Loop Breakers

Rate limiting stops runaway token burn.

4. Credential Injection

Injected at call-time; no API keys in images.

# NetworkPolicy: The Gateway is mandatory, not optional
kind: NetworkPolicy
spec:
  podSelector: { matchLabels: { app.kubernetes.io/part-of: agent-workload } }
  egress:
  - to: [{ podSelector: { matchLabels: { app: agent-gateway } } }] # Egress locked to gateway only

4. Observe + Evaluate 6:55–7:55

attributes:
  gen_ai.system: "gemini"

Per-agent cost attribution and automated loop detection come straight out of these telemetry lines.
